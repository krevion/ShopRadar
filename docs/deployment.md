# Production deployment

ShopRadar is a pnpm monorepo with a Next.js web app, a NestJS API, and a PostgreSQL database. Render configuration is defined in [`render.yaml`](../render.yaml), which provisions the web service, API service, PostgreSQL database, and persistent API upload disk in Frankfurt.

## Services to provision

- A Node.js 22 web service for `apps/web`.
- A Node.js 22 API service for `apps/api`.
- A managed PostgreSQL 16 database with network access from the API.
- A persistent disk mounted at `/var/data` for API video uploads. The API stores uploaded videos on disk; an ephemeral filesystem would lose them when the service restarts or deploys.

The Blueprint uses Render's default service domains, `shopradar-web.onrender.com` and `shopradar-api.onrender.com`. If those service names are unavailable or you later add custom domains, update `WEB_ORIGIN`, `API_PUBLIC_URL`, `MPESA_CALLBACK_URL`, and `NEXT_PUBLIC_API_URL` to match, then redeploy the services. `NEXT_PUBLIC_API_URL` must be set at build time.

**Cost note:** this configuration is not free-tier-only. The API's persistent disk requires a paid Render web service, and the Blueprint uses a paid PostgreSQL plan for durable production data. Review Render's current pricing and the selected region before deploying. The 1 GB upload disk can be increased later but not decreased.

## Production environment

Set these values in the hosting provider's secret/environment settings. Do not commit production secrets to `.env` or `.env.example`.

| Variable | Purpose |
| --- | --- |
| `NODE_ENV` | Set to `production` by the Blueprint. |
| `DATABASE_URL` | Linked to the Render PostgreSQL database by the Blueprint. |
| `JWT_SECRET` | Generated by Render for the API. |
| `ADMIN_PASSWORD_HASH` | Add a bcrypt hash of a strong admin password in Render; the Blueprint prompts for this secret. |
| `WEB_ORIGIN` | Exact HTTPS web origin used by API CORS; set by the Blueprint. |
| `API_PUBLIC_URL` | Public HTTPS API origin used in video links; set by the Blueprint. |
| `NEXT_PUBLIC_API_URL` | Public HTTPS API origin embedded at web build time; set by the Blueprint. |
| `UPLOADS_DIR` | `/var/data/videos`, under the API's persistent disk mount. |
| `PORT` | Set automatically by Render. |
| `TRUST_PROXY_HOPS` | Set to `1` for Render's reverse proxy so API client-IP rate limits use the forwarded client address. |
| `PAYMENTS_ENABLED` | Set to `false`; keep disabled until Safaricom production credentials and callback details are available. |

The API rejects production startup when the database URL, strong JWT secret, HTTPS web origin, HTTPS API origin, or absolute persistent upload path is missing or invalid. It also fails startup if PostgreSQL cannot be reached. The web build rejects a missing or non-HTTPS `NEXT_PUBLIC_API_URL`. `/api/health` is a liveness endpoint; `/api/ready` checks PostgreSQL and returns `503` until the API can serve database-backed requests.

## Build and release

In the Render Dashboard, create a new Blueprint from this repository and select the root `render.yaml`. Review the resources and costs, then provide `ADMIN_PASSWORD_HASH` when prompted. This value must be a bcrypt hash, not the plain admin password. The API build and release commands are:

```bash
corepack enable
pnpm install --frozen-lockfile
pnpm --filter @shopradar/database prisma:generate
pnpm exec turbo run build --filter=@shopradar/api...
pnpm --filter @shopradar/database migrate:deploy
```

The API build generates the Prisma client and builds its workspace dependencies. Render runs `migrate:deploy` as the API's pre-deploy command before starting each new API release. Do not run `migrate dev` against production. The web service separately runs `pnpm --filter @shopradar/web build`; `NEXT_PUBLIC_API_URL` is set before Next.js compiles the browser bundle.

Render uses Node.js `22.22.0`, pinned in `.node-version`, and automatically provides the `PORT` environment variable.

## Render deployment and health checks

The Blueprint configures Render's web health checks as `GET /healthz` and API readiness checks as `GET /api/ready`. The API readiness endpoint returns `200` only when PostgreSQL is available; `/api/health` is liveness-only and should not be used to route database-dependent requests.

- The API upload disk is attached to one Render API instance and is not shared across instances. Keep the API at one instance while video files are stored locally; move video storage to shared object storage before scaling horizontally.
- The public API cache and request/login rate limits are in-memory and per instance. Use a shared edge/WAF rate limit for authentication and registration if scaling the API.
- The API and web app may use custom domains. Update the Blueprint environment URLs and redeploy after adding domains; the browser API URL is compiled into the web bundle.

The repository does not contain Render account access, so creating the Blueprint, setting the admin password hash, reviewing billing, adding custom domains, and configuring DNS are completed in the Render Dashboard. Verify both health checks after deployment.

## Admin access

ShopRadar has one password-protected admin dashboard, hidden from the site navigation and only reachable through the site's admin shortcut followed by password verification. Generate a bcrypt hash with the API package's `admin:hash` command by providing `ADMIN_PASSWORD` as a temporary environment secret, then set `ADMIN_PASSWORD_HASH` in the API runtime environment. Remove the temporary plain password after generating the hash. Production startup requires both `ADMIN_PASSWORD_HASH` and a unique `JWT_SECRET`.

The admin login issues a 30-minute token for the single configured site owner. Public customer and seller registration cannot create admin sessions. Admin and user tokens use separate issuers and audiences; admin routes accept only the admin token. Login attempts are rate-limited per API process, so enable a shared Render/edge/WAF rate limit on `/api/admin/auth/login`, `/api/auth/login`, and `/api/auth/register` before running multiple API instances. The admin password is never stored in source control.

## Security and capacity

- Serve the website and API only over HTTPS. The web app and API set browser security headers, and private admin API responses are marked `no-store`.
- Use a unique random `JWT_SECRET` and a strong, unique admin password. Keep `.env` and all production secrets out of source control.
- User bearer tokens expire after one day by default; admin tokens expire after 30 minutes. Use the matching issuer and audience when verifying each token type.
- Set a PostgreSQL connection pool URL for the runtime API. Choose `connection_limit` and `pool_timeout` for the database plan and total API replica count; total connections across replicas must stay below the database limit. Use the provider's pooler for horizontally scaled APIs and a direct database URL for migrations when the provider requires it.
- The API is stateless for authenticated requests and can run multiple replicas. Add a load balancer and shared rate limiting before scaling; the in-process failed-login limiter is only a single-instance fallback.
- Activity timestamps used by the admin dashboard have database indexes. Monitor database connections, query latency, storage, and API error rates, and load-test against the selected Render plans before a public launch.

## External services and current limits

- Seller and catalog records, messages, notifications, reports, and video metadata use PostgreSQL.
- Video files require a persistent volume. Object storage support is not wired into the API yet.
- M-Pesa initiation and callbacks remain disabled. Do not set `PAYMENTS_ENABLED=true` until real Safaricom credentials and a public callback URL are ready.
- Buyer order and checkout endpoints are not implemented. The current launch scope supports product discovery, approved seller listings, seller contact, and maps; add an order flow if shoppers need to purchase in-app.
- Email verification and password recovery are not implemented; configure those before relying on email ownership for production account recovery.
- Configure a host-level rate limit for `/api/auth/login` and `/api/auth/register` using Render or an edge/WAF service. Review the domain, plan costs, database, and Blueprint configuration before deployment.
